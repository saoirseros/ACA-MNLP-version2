# Experimental Findings: Multi-Module NLP System for Real-Time Conversational Analysis

This document reports the results of the Phase 9 experiments defined in
[README.md](README.md). All numbers below were generated by running
`experiments/run_all.py` once, end-to-end, against the pretrained models
and Adaptive Context Activation (ACA) implementation currently in
`nlp-service/app/`. No number in this document is estimated, assumed, or
invented - each is read directly from the corresponding JSON file in
`experiments/results/`, which is regenerated (not manually edited) every
time the suite is re-run.

**Reproducibility**: fixed random seed (42) for all dataset sampling;
sample sizes and exact configuration are declared in `run_all.py`'s
`SAMPLE_SIZES` dict. Re-running the suite with the same seed and sample
sizes reproduces these figures; re-running with larger sample sizes will
change the exact numbers but is expected to be directionally consistent.

---

## 1. Research questions

This system makes two falsifiable claims that the spec required be
tested rather than assumed:

1. **RQ1 (per task):** How does a lightweight TF-IDF + Logistic
   Regression baseline compare to a pretrained Transformer, on
   accuracy/precision/recall/F1 and inference latency, for sentiment,
   emotion, and toxicity classification?
2. **RQ2 (central research question):** Can Adaptive Context Activation
   (selecting only relevant prior messages) maintain or improve
   conversational analysis quality while reducing unnecessary contextual
   processing, compared to a full/recent-context strategy?

---

## 2. Methodology

### 2.1 Models evaluated

| Task | Baseline | Transformer (as used in the live chat pipeline) |
| --- | --- | --- |
| Sentiment | TF-IDF (1-2 grams, 20k features) + Logistic Regression, trained on task's own train split | `distilbert-base-uncased-finetuned-sst-2-english` (pretrained, not further fine-tuned here) |
| Emotion | Same baseline architecture, trained on task's own train split | `j-hartmann/emotion-english-distilroberta-base` (pretrained) |
| Toxicity | Same baseline architecture, trained on task's own train split | `unitary/toxic-bert` (pretrained) |

**Important asymmetry, disclosed rather than hidden:** the baseline is
*trained* on each task's own training split (in-domain by construction).
The Transformer models are used exactly as they are used in the live
system - i.e. **pretrained, not fine-tuned on these specific evaluation
datasets** (per the project spec: "pretrained inference can be
demonstrated first and fine-tuning can be performed separately"). For
sentiment, this happens to still be a fair in-domain comparison, because
`distilbert-base-uncased-finetuned-sst-2-english` was originally
fine-tuned on SST-2 itself - the exact dataset used for evaluation here.
For emotion and toxicity, the Transformer is being evaluated **out of
its original training distribution** (see Section 4). This is a
meaningful methodological difference between tasks and should not be
glossed over when interpreting the comparison.

### 2.2 Datasets

| Task | Dataset | Split(s) used | n (train / test) |
| --- | --- | --- | --- |
| Sentiment | SST-2 (GLUE) | train / validation (used as test; GLUE's official test split is unlabeled) | 2000 / 300 |
| Emotion | dair-ai/emotion | train / test ("love" label excluded - no equivalent in the live model's label space) | 3000 / 300 |
| Toxicity (proxy) | tweet_eval (offensive config) | train / test | 3000 / 300 |
| Adaptive context | DailyDialog (`roskoN/dailydialog` mirror) | test | 40 dialogues, 251 evaluable turns |

All datasets are public and required no authentication to download. See
[README.md](README.md) for full source links and the rationale for using
`tweet_eval` as a toxicity proxy (Jigsaw's own dataset requires a Kaggle
login to fetch programmatically).

### 2.3 Evaluation protocol

For each classification task: the baseline is trained once per run on
its training sample, then both the baseline and the Transformer predict
**one example at a time** (not batched), matching exactly how the live
chat pipeline processes a single incoming message. Latency is measured
per-example in this same loop. Accuracy, macro/weighted precision,
recall, and F1, and a full confusion matrix are computed with
scikit-learn against the held-out test sample.

For the context experiment: DailyDialog dialogues are replayed turn by
turn. For every turn after the first (turns need *some* history to make
a context comparison meaningful), two inputs are built for the **same**
emotion classifier: (a) all preceding turns in that dialogue up to an
8-turn window (`FULL_CONTEXT_WINDOW`, matching ACA's own history
horizon) - "Experiment A"; and (b) only the messages ACA's scoring +
selection logic chooses - "Experiment B". Both conditions call the exact
same production code paths (`app.context.scoring`, `app.context.selector`,
`app.context.composer`, `app.models.emotion.model`) used by the live
system - this is not a re-implementation for the experiment.

## 3. Results

### 3.1 RQ1 - Baseline vs Transformer, per task

| Task | Approach | Accuracy | Precision (macro) | Recall (macro) | F1 (macro) | F1 (weighted) | Mean latency (ms) |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Sentiment | Baseline (TF-IDF+LR) | 0.703 | 0.724 | 0.695 | 0.691 | 0.693 | 2.8 |
| Sentiment | Transformer | **0.913** | **0.914** | **0.912** | **0.913** | **0.913** | 217.2 |
| Emotion | Baseline (TF-IDF+LR) | 0.673 | 0.438 | 0.331 | 0.339 | 0.634 | 6.6 |
| Emotion | Transformer | **0.930** | **0.629** | **0.634** | **0.631** | **0.930** | 259.5 |
| Toxicity | Baseline (TF-IDF+LR) | 0.807 | **0.897** | 0.623 | 0.640 | 0.759 | 4.9 |
| Toxicity | Transformer | **0.883** | 0.886 | **0.798** | **0.829** | **0.876** | 493.2 |

(Full classification reports and confusion matrices: `results/<task>_comparison.json` and `results/<task>_*_confusion_matrix.png`.)

**Observations:**

- The Transformer outperforms the baseline on every task by every metric
  except toxicity precision (macro), where the baseline is marginally
  higher (0.897 vs 0.886) - but at the cost of much lower recall (0.623
  vs 0.798): the baseline's confusion matrix shows it predicts "toxic"
  correctly only 19/77 times (recall 0.247) versus the Transformer's
  48/77 (recall 0.623) on this specific sample, i.e. the baseline is
  conservative and misses most actually-toxic messages while rarely
  false-alarming.
- The accuracy-vs-macro-F1 gap is large for emotion (baseline: 0.673 vs
  0.339; Transformer: 0.930 vs 0.631). This is a real, disclosed
  imbalance effect, not an error: `dair-ai/emotion`'s "disgust" and
  "neutral" labels never occur in this dataset (0 support), yet remain
  in the evaluated label set for consistency with the live model's full
  label space, mechanically pulling macro-averaged scores down for both
  approaches equally. Per the spec's own instruction ("do not blindly
  report accuracy when it is misleading"), macro-F1 is reported
  alongside accuracy specifically so this doesn't get hidden.
- Latency cost of using the Transformer instead of the baseline is
  substantial: roughly **77x** for sentiment, **39x** for emotion, and
  **101x** for toxicity (all on CPU, single-example, no batching). This
  is the direct predictive-quality-vs-computational-cost tradeoff the
  spec asks this project to make measurable, not assume.

### 3.2 RQ2 - Full-context vs Adaptive Context Activation

Evaluated on 251 turns across 40 DailyDialog dialogues (emotion
classification against ground-truth emotion labels):

| Strategy | Accuracy | Precision (macro) | Recall (macro) | F1 (macro) | F1 (weighted) | Avg. context size (words) | Mean latency (ms) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Full context (up to 8 prior turns) | 0.546 | 0.184 | 0.166 | 0.151 | 0.650 | 52.5 | 453.3 |
| Adaptive Context Activation | **0.625** | **0.203** | **0.255** | **0.191** | **0.711** | **11.7** | 665.3 |

(Full data: `results/context_experiment_comparison.json`; confusion
matrices and charts: `results/context_*`.)

**Headline result:** in this experiment, ACA achieved **higher accuracy
(+7.97 points, +14.6% relative), higher macro-F1 (+0.040, +26.6%
relative), and higher weighted-F1 (+0.061)** than the full-context
strategy, while using **77.8% less context on average** (11.7 words vs
52.5 words) - a genuinely favorable result for the project's central
hypothesis on the predictive-quality side.

**However, ACA's measured wall-clock latency was higher, not lower**
(665.3ms vs 453.3ms mean, +46.8%). This is not a contradiction of the
efficiency claim - it is a distinct, disclosed cost: the "adaptive"
condition's latency includes the cost of *deciding* how much context to
use (embedding the message + recent history with `all-MiniLM-L6-v2` and
scoring four signals), on top of running the (smaller) input through the
emotion classifier. The full-context condition pays no such decision
cost - it always uses a fixed window. On this CPU-only setup, the
decision overhead outweighed the inference-time savings from a smaller
input. Whether this holds on GPU hardware, with a lighter-weight
similarity method, or at larger context sizes (where the input-size
savings would matter more) is an open question this experiment does not
answer and is not claimed to.

Context distribution is heavily skewed toward the majority "neutral"
class (216 of 251 evaluated turns, 86.1%) - a known property of
DailyDialog (most everyday utterances are affectively neutral). This is
why accuracy for both strategies is dominated by how well "neutral" is
predicted, and why macro-F1 (which treats all 7 emotion labels equally)
is much lower than accuracy or weighted-F1 for both conditions - again,
reported explicitly rather than only citing the more flattering accuracy
number.

## 4. Discussion

**RQ1** is answered affirmatively for predictive quality but with an
explicit, large latency cost: the pretrained Transformers meaningfully
outperform the TF-IDF+LR baseline on every task tested, at 39-101x the
per-example latency. Whether that tradeoff is worth it depends on the
deployment's latency budget - this project's live chat pipeline accepts
it because analysis runs asynchronously and never blocks message
delivery (see Phase 4-7 of the main project).

The emotion and toxicity comparisons are **not** in-domain for the
Transformer the way sentiment is: `j-hartmann/emotion-english-distilroberta-base`
was not fine-tuned on `dair-ai/emotion`, and `unitary/toxic-bert` was
trained on Jigsaw's Wikipedia-comment data, not `tweet_eval`'s Twitter
data. That the pretrained Transformer still outperforms an in-domain-
trained baseline on both tasks is a real finding worth noting, but it
should be read as "pretrained, general-purpose models generalize
reasonably well even off their original training distribution here" -
not as "fine-tuning would not help further." Fine-tuning these models on
each task's actual training data (the `training/` scaffold in this
repository is built for exactly this) would very plausibly close or
reverse some of this gap and is the natural next experiment.

**RQ2** is the more novel contribution. The result is genuinely mixed
rather than a clean win, and is reported that way: ACA improved
predictive quality and drastically reduced context size, but did not
reduce measured latency in this implementation, because the cost of
*deciding* what context to use was not negligible relative to the
(already fast) emotion classifier itself. This is a legitimate, useful
finding for the paper - it shows adaptive context selection is not a
"free win" and quantifies exactly where its cost currently sits,
pointing directly at where future optimization work (e.g. caching
embeddings across turns, using a cheaper heuristic-only signal set
before falling back to embeddings, or batching the similarity
computation) should focus.

## 5. Limitations

- **Sample sizes are modest** (300 test examples per classification
  task; 40 dialogues / 251 turns for the context experiment), chosen to
  keep the full suite runnable in minutes on a CPU-only development
  machine. Larger samples would narrow confidence in these estimates;
  the code is unchanged if sample sizes are increased (see README.md).
- **No statistical significance testing** (e.g. bootstrap confidence
  intervals or paired significance tests) is performed between
  baseline/Transformer or full/adaptive conditions. The differences
  reported (e.g. +14.6% relative accuracy for ACA) should be read as
  point estimates from a single run with a fixed seed, not as
  statistically validated effects.
- **Toxicity is evaluated on a proxy dataset** (`tweet_eval` offensive
  language, Twitter) rather than the live model's original training
  distribution (Jigsaw, Wikipedia comments), because the latter requires
  Kaggle authentication to download programmatically. Toxicity numbers
  here measure cross-domain generalization, not in-domain performance.
- **Emotion label space mismatch**: `dair-ai/emotion` covers 6 labels,
  the live model covers 7; "love" (no live-model equivalent) is
  excluded, and "disgust"/"neutral" have zero true support in this
  particular test sample, which mechanically affects macro-averaged
  metrics for both approaches (equally, but still worth flagging).
- **The context experiment uses emotion classification only** (not
  sentiment/toxicity) as its predictive-quality proxy, since DailyDialog
  provides real per-utterance emotion labels but not sentiment/toxicity
  labels for the same utterances. Whether ACA's effect on predictive
  quality generalizes to sentiment/toxicity classification is untested.
- **Latency figures are wall-clock, single-machine, single-process, CPU-only**
  measurements from one run each; no attempt is made to isolate/average
  out OS scheduling noise or background load beyond reporting the full
  latency distribution (mean/p50/p95/min/max) rather than a single number.

---

## 6. Conclusion

Neither research question was assumed to have a particular answer
before running these experiments, per the project's explicit constraint
against fabricating or presupposing results. What the data actually
shows:

- Pretrained Transformers substantially outperform a TF-IDF+Logistic
  Regression baseline on sentiment, emotion, and toxicity classification
  in this evaluation, at a latency cost of roughly 40-100x.
- Adaptive Context Activation, as currently implemented, **improved**
  predictive quality (accuracy and F1) while using **~78% less context**
  than a full-context strategy on a real, labeled, multi-turn dialogue
  benchmark - but at a **higher measured latency**, due to the cost of
  the context-selection decision itself rather than the cost of running
  the classifier on a smaller input.

This is a genuinely mixed, non-predetermined result, and is reported as
such: adaptive context selection is not a strictly dominant strategy
over full context in this implementation - it trades a latency cost
(the decision overhead) for a quality and context-size benefit. Whether
that trade is worthwhile depends on the deployment constraint being
optimized for, and is exactly the kind of question this experimental
infrastructure was built to keep measuring as the system evolves.
